## Decisions

- Preserve Anarlog's UI, native audio backend, providers, account/entitlement rules and Linux/Windows paths. This is a behavior and engine port, not an Electron or Char UI port. No API service, billing or model migration is needed merely to use Char's dictation behavior.
- Share deterministic text rules in a small `crates/dictation-core` crate, usable by Tauri and future native consumers. Keep native capture, temporary file ownership and operation cancellation in the existing dictation plugin. Reuse existing STT/LLM adapters; avoid a second provider registry or a general workflow framework.
- Run the new orchestration behind an internal opt-in until combined regression checks and later device acceptance pass. Optional cleanup, external context, learning, output ducking and durable recovery remain off unless explicitly enabled. Existing dictation settings keep their meaning.
- A dictation owns account/library + surface + fresh operation ID + captured destination. Every asynchronous result is checked against that identity. Account changes, cancellation, surface disposal and meeting start retire it; late results neither upload under another account nor insert text.
- Raw/local routes are preserved. Cleanup and transcription are separate choices: selecting local transcription does not authorize cloud cleanup. Resolve explicit current policy before either request, and refuse unreadable policy instead of falling back remotely.
- Keep one final delivery. Preview words are not insertion. For suffix recovery, trust only a provider's proven committed boundary; otherwise re-transcribe the complete retained audio and replace the provisional aggregate before insertion. Do not guess completeness from nonempty text.
- Native insertion remains tied to the field captured at start. Readback distinguishes applied, definitely unchanged and uncertain. Never retry a potentially applied edit. Preserve Anarlog's clipboard-provider acknowledgement and user clipboard changes rather than replacing it with Char's fixed 250 ms restore timer.
- Selection editing requires the same field and unchanged selected content/fingerprint at commit time. Cleanup failure may keep raw dictated text; editing failure never substitutes the spoken instruction for the selection. A continuation edit and raw-text restoration need the same guarded target/content check.
- Context snapshots are bounded, ephemeral and operation-scoped. Unknown privacy state supplies no external context. Browser titles alone cannot establish an allowed host. No screen text, selected text, transient context or raw credentials enters recovery files or telemetry.
- Recovery is explicit opt-in: private files, at most 20 pending dictations, 100 MiB total and 24-hour expiry; fail without silently evicting a current operation when full. Delete audio after durable text adoption, and on discard/expiry/account retirement according to the chosen account policy. Never silently upload a previously local recording after a preference changes. Recovered text is offered for explicit use/copy, not automatic insertion into stale apps.
- Char's continuous passive typing sampler and Awareness history collection are outside this engine migration. Optional post-dictation correction learning and bounded destination samples cover the relevant dictation behavior without importing a new background capture product.
- Source is GPL-3.0-or-later and Anarlog's provenance policy requires written approval before incorporating GPL material. Record all copied/translated/reference paths accurately; no approval or relicense is established. Local implementation authorization does not establish publication clearance. No push, PR, release, live dictation, external text insertion, camera/mic capture or secret retrieval is authorized in this batch.

## Four implementation lanes

All agents use Claude Opus 5.5 at extra-high effort, the existing shared GitButler workspace and one coherent local branch, `refactor/char-dictation`. They commit only owned files/hunks. No worktrees, branch switching, pulls, history rewriting, global memory writes or nested agents. Other meeting and GPUI agents remain active; do not modify their files. The parent handles final review and integration verification.

1. **Capture, streaming and operation foundation.** Own `plugins/dictation` except the insertion module, new recovery files and generated dictation contracts. Own narrowly required root Cargo registration/lock edits for `dictation-core`; preserve unrelated lockfile edits. Publish concrete operation/config/result types first in `/tmp/anarlog-char-dictation-20261117/contracts.md`. Adapt the existing recorder/preview to bounded early audio, phrase fallback, explicit readiness/finalization, captured provider policy, generation-aware cancellation and opt-in recovery. Provide a small surface-neutral API for system/chat; no renderer or native insertion changes. Coordinate volume helper hooks with lane 3. No changes to meeting capture engines or provider defaults.
2. **Text, cleanup and contextual hints.** Own and extend the existing `crates/dictation-core` with pure text fitting/replacements, cleanup/edit prompt construction and reply validation, term ranking/weights/correction suggestions and bounded privacy/context decisions. Own a narrow new frontend LLM adapter where needed, not the system/chat controllers. Reuse Anarlog's selected model and auth-fetch route via supplied ports; do not implement another credential service. Use Char's behavior/tests as references and record provenance. Provide exact configuration fields/commands to lanes 1 and 4. Context collection is explicit and stops at the operation boundary.
3. **Targeted insertion, shortcuts and output ducking.** Own `plugins/dictation/src/insertion`, `crates/dictation-ui-macos`, `plugins/shortcut` and their native modules. Add guarded selected-text/context reads, insertion outcomes, continuation/raw restoration where provable, hold/latch/cancel gestures, and an opt-in output ducker with safe restoration. Keep platform implementations compiling and preserve Wayland limitations honestly. Request command/binding registration from lane 1 instead of editing its files. No real foreground-app writes or hardware trials.
4. **App integration and settings.** Own `apps/desktop/src/dictation`, chat's `use-dictation.ts`, dictation/dictionary settings and narrowly scoped setting definitions. Integrate lanes 1–3 into both current entry points, with existing providers/entitlements, scoped account teardown, one final delivery and coherent failure/retry UX. Use existing Anarlog controls; no Char overlay/settings reproduction. Implement optional settings and recovery actions, approved-context collection and post-dictation correction-learning wiring. Keep default behavior intact while opt-in is off. Coordinate Lingui/catalog generation with the meeting settings owner; do not edit its settings or bridge files.

## Acceptance and rollout

Automated acceptance must exercise the complete path with fake audio/provider servers and a fake target, not only private helper tests: press/open/stop/cancel races; short taps; one recorder across system/chat; stream failure before/after final words without loss or duplication; suffix/full fallback timing; queue bounds; local-only policy; account change during transcription/cleanup/retry; phrase silence and duration cap; unchanged selections and moved focus; uncertain native writes; clipboard/volume ownership; multilingual replacements and caret fitting; cleanup deadline versus edit failure; recovery across crash/expiry/discard; existing provider, platform and meeting exclusion compatibility.

Use regression tests that fail against the old behavior, relevant crate tests/Clippy, generated-binding stability and desktop typecheck/tests/i18n/lint as required by current workflows. Baseline tooling failures must be reported separately. No benchmark or latency claim without measurements. No native feature claim from TypeScript checks alone.

The local batch is complete only when both system and chat dictation use the opt-in engine through real app adapters, deterministic tests exercise recording-to-final-delivery/recovery, defaults remain compatible, and every material limitation is documented. Live qualification is separate: signed TCC, first-word capture, route/Bluetooth changes, shortcut conflicts, real app AX edits, clipboard timing, output ducking and local/provider performance. Only then consider default cutover; publication additionally needs provenance clearance.
