# Tauri desktop inventory (ANLG-320, Phase 0)

Every Tauri command, plugin, window, frontend route, background service, and OS
integration in `apps/desktop`, mapped to what happens to it in the GPUI
migration. Generated from `main` at `38d2fc67d` by walking
`plugins/*/permissions/autogenerated/commands`, `apps/desktop/src-tauri/src`,
and `apps/desktop/src`. Regenerate the counts and the appendix when plugins
change; the mapping column is a decision and must be edited by hand.

Mapping legend:

- **core** — already runtime-neutral Rust in `crates/*`; GPUI calls it directly.
- **extract** — logic lives inside the Tauri plugin crate and must move to a
  shell-neutral service in `crates/*` first (Phase 1). Tauri keeps a thin
  adapter; GPUI calls the service.
- **gpui** — WebView- or Tauri-specific surface that needs a native GPUI
  implementation (UI, window chrome, platform glue).
- **remove?** — exists only to serve the WebView. Candidate for approved
  removal; nothing is removed without an explicit decision.

Nothing here changes the SQLite schema, the TipTap-dialect document format,
settings files, vault layout, or the CloudSync protocol.

## Phase 1 extraction order

Ordered by trapped logic (plugin LOC without a backing service) and by how many
frontend areas depend on it. Each item becomes a runtime-neutral crate with
contract tests that Tauri and GPUI adapters both pass.

1. `db` (14.2k): CloudSync lifecycle, E2EE identity, startup status, legacy
